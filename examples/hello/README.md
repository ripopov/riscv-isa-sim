# Bare-Metal Hello World for Spike

This directory contains a bare-metal "Hello World" example for the RISC-V Spike simulator.

## Files

- **hello_htif.c** - Bare-metal C source that prints "Hello, world!" using HTIF syscalls
- **baremetal.ld** - Linker script for bare-metal programs
- **run_hello.sh** - Script that compiles, runs, and verifies the output
- **hello_htif.elf** - Compiled executable (generated by run_hello.sh)
- **hello_htif.dis** - Disassembly of the executable (generated by run_hello.sh)
- **hello_trace.log** - Instruction execution trace with register changes (generated by run_hello.sh)
- **hello_commit.log** - Commit log showing only register changes (generated by run_hello.sh)

## Usage

Simply run the script:

```bash
./run_hello.sh
```

The script will:
1. Compile `hello_htif.c` using `riscv64-unknown-elf-gcc`
2. Generate disassembly of the executable
3. Run the executable on Spike with instruction tracing enabled
4. Generate two trace files:
   - `hello_trace.log` - Full execution trace (PC + disassembly + register changes)
   - `hello_commit.log` - Commit log showing only changed registers/memory per instruction
5. Verify that the output matches the expected result

## How It Works

The bare-metal program uses Spike's HTIF (Host-Target Interface) to communicate with the host:

1. **HTIF Protocol**: Communication happens through two special variables:
   - `tohost`: Target writes commands here
   - `fromhost`: Host writes responses here

2. **Syscall Mechanism**:
   - A "magic memory" region holds syscall number and arguments
   - Writing the address of this region to `tohost` invokes the syscall
   - The host processes the syscall and writes response to `fromhost`

3. **sys_write**: The program uses syscall #64 (write) to print to stdout

## Requirements

- `riscv64-unknown-elf-gcc` toolchain
- Spike simulator (built in `../../build/spike`)

## Technical Details

- **ISA**: RV64G (RV64IMAFDC)
- **ABI**: lp64d (64-bit with double-precision float)
- **Entry Point**: `_start`
- **Load Address**: 0x80000000 (Spike's default)
- **No Dependencies**: Fully bare-metal, no standard library or proxy kernel needed

## Trace Log Formats

The script generates two types of trace logs:

### Basic Trace (`hello_trace.log`)
Generated with `-l --log-commits` flags. Shows PC, instruction encoding, disassembly, and changes:
```
core   0: 3 0x0000000080000000 (0x00000797) x15 0x0000000080000000
```
Format: `core <id>: <priv> <pc> (<encoding>) <reg> <new_value>`

### Commit Log (`hello_commit.log`)
Generated with `--log-commits` flag only. Shows register and memory changes per instruction:
```
core   0: 3 0x000000008000000c (0x00e7b023) mem 0x00000000800000c0 0x0000000000000040
```
- `xN` - Integer register (x0-x31)
- `fN` - Floating-point register (f0-f31)
- `vN` - Vector register (v0-v31)
- `mem <addr> <value>` - Memory write
- `mem <addr>` - Memory read

This is useful for verifying instruction behavior and debugging.
